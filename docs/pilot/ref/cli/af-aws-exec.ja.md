# af-aws-exec

[English](af-aws-exec.md) | 日本語

**AWS プロファイル 1 つの短命の資格情報で、コマンドを 1 つ実行します。**
資格情報はそのコマンドにだけ環境変数で渡されます。使い方の流れは [AWS SSO を使う](../../user/integrations/aws-sso.ja.md) を見てください。

## 書式

```sh
af-aws-exec --profile <名前> [--account <ID>] [--region <リージョン>] [--login | --no-login]
            [--keep-aws-config] [-q] -- <コマンド> [引数...]
af-aws-exec --list
af-aws-exec --help
af-aws-exec --version
```

`--` より後ろが、実行するコマンドです。

## オプション

| オプション | 意味 |
|---|---|
| `--profile <名前>` | 使うプロファイル。必須です。名前は `--list` で確かめられます |
| `--account <ID>` | プロファイルのアカウントがこの ID でなければ、何も実行せずに止めます。設定画面のプロファイル**以外**（自分で `~/.aws` に定義したもの）では必須です |
| `--region <リージョン>` | コマンドに渡すリージョン。下の「リージョンの決まり方」を参照 |
| `--login` | ログインが使えないとき、この端末で device-code のログインを始めます |
| `--no-login` | ログインを求めず、ログイン用のコマンドを表示して終了コード 3 で終わります |
| `--keep-aws-config` | 自分の `~/.aws` のファイルと `AWS_ENDPOINT_URL*` の設定を、コマンドにもそのまま渡します（下の「コマンドに渡す設定」を参照） |
| `-q` | 実行する身元の行を表示しません |
| `--list` | 設定からプロファイルを読み直して、使える名前を一覧にします |
| `-h`, `--help` | ヘルプを表示します |
| `--version` | バージョンを表示します |

## ログインが必要なとき

`--login` も `--no-login` も付けないと、ワークスペースの中では **Console にログインを依頼して待ちます**。
Console に「エージェントが AWS へのログインを待っています」のトーストが出て、承認されるとコマンドが続きます。
端末で実行したときも同じです。待っている間に Ctrl-C を押すと、終了コード 3 で終わります（依頼は Console に残ります）。

## 出力

コマンドを実行する前に、標準エラーに次の 1 行を出します（`-q` で消せます）。

```
af-aws-exec: running as arn:aws:sts::222222222222:assumed-role/AWSReservedSSO_Developer_…/you@example.com in region ap-northeast-1 (expires …)
```

実際にどのアカウント・ロールで動くかは、この行で確かめられます。

## 終了コード

| コード | 意味 |
|---|---|
| コマンドのもの | 実行できたときは、コマンド自身の終了コードをそのまま返します |
| 1 | そのほかの拒否・失敗（アカウントが `--account` と違う、など） |
| 2 | 使い方の誤り |
| 3 | ログインが必要なのに始めなかった（`--no-login`、Console で時間内に承認されなかった、待っている間に Ctrl-C） |
| 4 | 「使用前に確認」のプロファイルで、Console で拒否された・時間内に答えがなかった・Agent Fleet のセッションの外から実行された |

終了コード 4 のとき、依頼は Console に残っています。許可してから、もう一度実行してください。

## リージョンの決まり方

上から順に、最初に見つかったものを使います。

1. `--region` の値
2. シェルにすでにある `AWS_REGION`、次に `AWS_DEFAULT_REGION`
3. プロファイルの既定リージョン

コマンドには `AWS_REGION` と `AWS_DEFAULT_REGION` の両方で渡します。
シェルに古い `AWS_REGION` が残っているとプロファイルのものより優先されるので、デプロイでは `--region` を付けてください。

## コマンドに渡す設定

既定では、コマンドに渡す AWS の設定には**選んだプロファイルだけ**が入っています。
そのため、ツールが別のプロファイルを指定していると（Terraform の `profile = "staging"` など）、
別のアカウントで動くのではなく `The config profile (staging) could not be found` で失敗します。

このときは、ツール側のプロファイル指定を外すか、そのプロファイルを `--profile` で指定してください。
**`--keep-aws-config` で回避しないでください。** ツールが自分で指定したプロファイルで動いてしまいます。

## 使えるプロファイル

| プロファイル | 扱い |
|---|---|
| 設定画面の SSO プロファイル | そのまま使えます |
| 設定画面の「別のプロファイルからロールを引き受ける」プロファイル | そのまま使えます。`--account` は要りません |
| 「使用前に確認」がオンのプロファイル | `af-aws-exec` からだけ使えます（`~/.aws/config` には書き出されません） |
| 自分で `~/.aws` に定義した、`source_profile` でロールを引き受けるプロファイルや `credential_process` のプロファイル | `--account` を付ければ使えます |
| 長期のアクセスキー、`credential_source`、web identity、`mfa_serial` を使うプロファイル | 使えません |

## `--list` の見方

1 行に 1 つ、`名前　アカウント　ロール　（ラベル）` の順に並びます。
`~/.aws/config` に書き出されなかったプロファイルは、`(not exported: …)` の形でその理由が出ます
（同じ名前になるラベルが 2 つある、自分の `~/.aws` に同じ名前の定義がある、など）。

## 実行の記録

実行のたびに、実行したセッションの会話に記録が残ります。プロファイル・アカウント・ロール・リージョン・プログラム名
（`aws` ならサービスと操作）、または拒否した理由です。**コマンドの引数は記録しません。**
全セッション分は、設定の「AWS プロファイル/SSM」にある **「最近の実行」** で見られます。
