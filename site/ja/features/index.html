エージェントのまわりのことを、1 か所で

トップページでは考え方を紹介しました。このページでは、それが実際に何になるかを見せます。まず使い方の例を 5 つ、続いて機能の一覧。数字があるものは数字を添え、利用ガイドの該当ページにつないでいます。

  • 既定はオフ使う前に誰かがオンにする
  • AWS 版のみAWS の版に依存する
  • 実験的変わるかもしれない試作

使い方の例

5 つの使い方

デモ用のバックエンドにつないだ Console で録画しました。クリックすると大きく表示します。

3 つのエージェントにレビューを分担させる 既定はオフ

Claude のセッションが設計レビューを 3 つに分け、それぞれを別のエージェントに任せます。

  1. Claude の親が子セッションを 3 本起動します。データモデルとマイグレーションは Codex、API の互換性は Antigravity、UI への影響は Muse Code。
  2. 子はそれぞれ自分の worktree で作業し、終わったら 1 回だけ報告するよう頼まれています。
  3. 親が 3 本の報告をまとめます。フリート俯瞰図には 4 本のレーンが時間軸に並び、起動とメッセージが矢印で描かれます。

「セッションからのセッション起動」と「セッション間メッセージ」は、どちらもオンにするまで使えません。子の同時本数は既定 3 本（1〜10）です。

障害の調査から修正まで 実験的

アシスタント 2 つで役割を分けます。片方は監視を読み、もう片方が作業を始めます。

  1. SRE アシスタントに、PagerDuty でいま開いているものを聞きます。インシデントを読み、CloudWatch のメトリクスとログから原因を絞り込みます。
  2. SRE アシスタントは読み取り専用で、何も変更できず、セッションも起動できません。そこで修正はフリート・オペレーターに頼みます。
  3. フリート・オペレーターが新しい worktree で Codex のセッションを起動して修正を任せ、そのセッションの報告は同じ会話に届きます。

アラートがチャットに自動で届くことはなく、こちらから聞きます。PagerDuty・Grafana・CloudWatch・AWS は「設定 › 運用・監視」で接続します。

利用ガイドの「運用ツール」→

チケットから PR、そしてレビューまで

左ペインの「課題管理」に、自分宛ての仕事が集まります。

  1. クエリを保存すると、GitHub の issue とプルリクエスト、Jira の課題、Bitbucket のプルリクエストが 1 つの一覧に並びます。
  2. 課題からセッションを起動すると、ブランチ名が命名規則から入ります（例: feature/45-empty-list）。作業は新しい worktree で。
  3. プルリクエストを開くと、CI・競合・レビューが見えます。「レビューを始める」で、その PR の head ブランチを新しい worktree に取り出します。

一覧の行に CI と競合の印が付くのは GitHub のプルリクエストです。Bitbucket は詳細で確かめます。

利用ガイドの「課題管理」→

プランを承認して、コミットまでブラウザで

この流れに端末は要りません。

  1. プランモードで起動すると、エージェントはまずプランを出します。その場で承認するか、指摘を書き込むか、別のセッションにレビューさせます。
  2. 作業が始まります。作業コピーの変更は会話のすぐ隣に出ます。
  3. ステージとコミットは、コミットグラフビューで自分で行います。作業コピーごとの本物の git です。

利用ガイドの「会話を読む・返信する」→

スマホで答える

席を離れていても、Console はスマホのブラウザで動きます。

  1. セッション一覧で、どのセッションが自分を待っているかが分かります。
  2. 開いて、カードの質問に答えます。席にいるときと同じ操作です。
  3. 止まったところから続きを進め、一覧には完了と出ます。

チャットブリッジをつなぎ「返信で操縦（双方向）」をオンにすれば（既定はオフ）、そのセッションの Slack や Discord のスレッドからも答えられます。

利用ガイドの「スマホでの操作」→

夜間の定時実行や、利用上限の後の自動再開は、トップページの「Agent Fleet のある一日」で紹介しています。

セッション同士の協調

セッションが別のセッションを起動し、メッセージを送り合えます。フリート・オペレーターがあなたの代わりにセッションを起動し、指示します。

  • 子セッション 既定はオフ

    1 本のセッションが子を既定で同時 3 本まで（1〜10）起動できます。9 種類のエージェントのどれでもよく、それぞれ新しい worktree で動きます。孫は作れません（1 段まで）。子は終わったら 1 回報告するよう頼まれます。

    利用ガイド →

  • セッション間メッセージ 既定はオフ

    依頼・質問・回答・共有の 4 種類。止まっている相手は再開してから受け取ります。1 通 16 KiB まで、送り手ごとに 1 分 6 通まで。

    利用ガイド →

  • フリート俯瞰図

    セッションごとのレーンを時間軸に並べ、子は親の下に置きます。起動・引き継ぎ・指示・メッセージはすべて矢印で描きます。

    利用ガイド →

  • プランを別のモデルにレビューさせる

    承認待ちのプランから「別セッションでレビュー」を選び、別のエージェントとモデルにレビューさせます。

    利用ガイド →

  • フリート・オペレーター

    セッションの起動・指示・停止・再開を代わりに行う組み込みのアシスタント。資源を使う起動の前には確認を取ります。

    利用ガイド →

  • セッション報告と自動走行 既定はオフ

    セッションは、手が空いたとき・質問するとき・異常終了したときにオペレーターへ報告します。自動走行をオンにすると決まりきった質問には自分で答えます。無人での返信は既定 10 回、最大 50 回。

    利用ガイド →

  • 引き継ぎ

    会話を別のエージェントへ引き継ぎます。要約はオペレーターが下書きし、あなたが確かめてから始まります。

    利用ガイド →

ファイルを読む・直す

エージェントが書いたものもチームの資料も、Console の中のファイルビュアーで開けます。

  • コード

    約 30 言語のハイライト、git が変更と見る行の印、10,000 行までのミニマップ。

    利用ガイド →

  • Markdown と Mermaid

    Mermaid の図をその場で描き、前付けは項目の一覧で見せます。path:行 のリンクはそのファイルのその行を開きます。

    利用ガイド →

  • Marp スライド

    marp: true の Markdown はスライドとして開きます。

    利用ガイド →

  • draw.io の図

    ネットにつながなくても表示できます。表示のみで、編集できるのは XML です。

    利用ガイド →

  • PDF

    文字を選択でき、拡大もできます。フォントを埋め込んでいない日本語の PDF も表示できます。

    利用ガイド →

  • Office・ODF・EPUB

    Word・Excel・PowerPoint・OpenDocument・EPUB を、ブラウザの中で Markdown に変換して見せます（40 MB まで）。簡易プレビューなので、書式・図形・画像は再現しません。

    利用ガイド →

  • 画像とギャラリー

    PNG から AVIF・SVG まで、8 倍まで拡大できます。ギャラリーのペインに画像が集まり、生成した画像の設定はワンクリックで見られます。

    利用ガイド →

  • 編集と AI の提案

    保存の競合を検出します。AI が提案した書き換えは、適用する前に差分で確かめられます（1 回の変更は 2 MiB まで）。

    利用ガイド →

  • まだ対応していないもの

    数式（KaTeX）、CSV の表表示、Jupyter ノートブック、動画・音声。これらはテキストとして開くか、開けません。

    利用ガイド →

  • CI と競合がひと目で

    GitHub のプルリクエストは一覧の行に CI と競合の印が付きます。詳細では CI・競合・レビュー・差分の量が見えます。

    利用ガイド →

  • チケットに合わせたブランチ名

    課題から起動すると、ブランチ名と分岐元が命名規則から入ります。

    利用ガイド →

    利用ガイド →

Console の中の Git

作業コピーと worktree ごとに本物の git を。並行作業に要る後片付けも揃っています。

  • コミットグラフ

    ブランチのレーンと差分、ステージとコミット、サブモジュールのグラフまで。

    利用ガイド →

  • worktree と親の差

    worktree ごとに、親と比べた状態（同じ・未マージ・早送り可・分岐）を表示します。早送りはワンクリック。

    利用ガイド →

  • ごみ箱から復元

    worktree を消しても、コミット・ブランチ・未コミットの変更を残します。復元すると同じ場所に、セッションごと戻ります。

    利用ガイド →

  • 内蔵の Git ホスティング

    Git LFS 付きの内部リポジトリを、テナントの中で共有できます。数と LFS の容量は管理者が決めます。

    利用ガイド →

  • サブモジュールと LFS

    サブモジュールはクローンと一緒に取得します。SSH の URL は認証が通るよう HTTPS に書き換えます。

    利用ガイド →

  • Git Flow

    リポジトリの行から Git Flow を初期化できます。書くのは設定だけで、コミットもチェックアウトもしません。

    利用ガイド →

  • Subversion

    SVN のリポジトリもチェックアウトできます（認証情報は保存可）。worktree とコミットグラフはありません。

    利用ガイド →

エージェントのまわりの開発環境

データベース、ブラウザ、プレビューをワークスペースの中に。Docker は要りません。

  • 作業コピーごとのデータベース

    作業コピーごとに Postgres または MySQL 8.4。Docker は要りません。30 分つながりが無ければサーバーは止まります。

    利用ガイド →

  • ブラウザペイン

    開発サーバーを Console の中の本物のブラウザで。HMR・WebSocket・Cookie も動きます。ワークスペースごとに 2 つまで、PC とタブレットで使えます。

    利用ガイド →

  • プレビュー URL AWS 版のみ

    ポートごとの URL を、テナントの人に見せたり、一時的にサインインなしで開けるようにしたりできます。プレビュー用サブドメインを発行する配備でだけ使えます。

    利用ガイド →

  • ブラウザを人に渡す

    エージェントがワンタイムコードの入力で止まったら、そのページを人に渡します。コードを入れて「操作完了」を押すだけです。

    利用ガイド →

  • 本物の端末

    エージェントでも素のシェルでも、どのセッションにも端末（PTY）としてつなげます。スマホには制御キーの列が出ます。

    利用ガイド →

チャットとアシスタント

自分で形を決めるアシスタントと、エージェントを読む・答えるための助け。

  • 自分のアシスタント

    アシスタントに人物像、エージェントとモデル、ツールの権限（なし・AF 読み取り・AF 書き込み）を決めて作れます。

    利用ガイド →

  • ターンを使わない翻訳

    「翻訳」は、セッションの外で 1 回だけモデルを呼び、エージェントの回答を自分の言語で読ませます。

    利用ガイド →

  • 返信候補

    自分の過去の返信から学ぶ候補のチップ。AI は使いません。✨ を押したときだけ AI に聞き、トークンを使います。

    利用ガイド →

  • 圧縮しても残る作業計画

    長くなったアシスタントの会話を圧縮しても（90% を超えると自動）、作業計画は一字一句そのまま引き継ぎます。

    利用ガイド →

  • 発言から分岐

    自分の過去の発言から会話を分岐させ、元の流れを残したまま別の方向を試せます。

    利用ガイド →

  • 会話の途中でエージェントを替える

    アシスタントの会話を、続きのまま別のエージェントやモデルへ移せます。

    利用ガイド →

  • Slack と Discord 既定はオフ

    セッションごとにスレッドができます。「返信で操縦（双方向）」をオンにすれば、そこからボタンで答えられます。

    利用ガイド →

運用と SRE

監視をチャットから読み、AWS のコマンドは自分として実行します。

  • SRE アシスタント 実験的

    PagerDuty・Grafana・CloudWatch・AWS を読みます。読み取り専用で、セッションは起動できません。アラートが自動で届くこともなく、こちらから聞きます。

    利用ガイド →

  • AWS のツールは読み取りから

    Agent Toolkit for AWS は読み取り専用で始まります。書き込みのツールは別のスイッチで、実際のリソースを変更できます。

    利用ガイド →

  • AWS コマンドの口座ガード

    af-aws-exec は自分のプロファイルでコマンドを実行し、指定したアカウントのものでなければ断ります。ワークスペース自身のロールに黙って切り替わることはありません。

    利用ガイド →

  • SSM でログイン

    社内のホストへ SSM Session Manager で入ります。サインインは IAM Identity Center で、AWS の秘密情報を Agent Fleet に保存しません。

    利用ガイド →

MCP

エージェントに自分のツールを渡し、外から Agent Fleet を操作します。

  • 自分の MCP サーバー

    stdio またはリモート HTTP のサーバーを登録できます。秘密情報は暗号化して保存します。セッションと、自分で作ったアシスタントに付けられます。

    利用ガイド →

  • 外部の Claude から操作

    Claude Code や Claude Desktop から、MCP トークンで自分のワークスペースを操作できます。範囲は読み取り・書き込み・管理の 3 段階。期限は既定 90 日で、取り消せます。

    利用ガイド →

  • テナントに配る

    テナント管理者が、リモートの MCP サーバーをテナント全員に一度に配れます。

    利用ガイド →

  • 外部通信の統制

    配備の運用者は、MCP の外向き通信を許可リストで記録または制限できます。メンバーは設定から許可を申請します。

    利用ガイド →

画像生成と自前のエンジン

管理者がエンジンを用意した環境では、画像の生成もオープンなモデルの実行も配備の中で行えます。

  • スタジオ

    エージェントと話しながら下書きを直します。エージェントが試せるのは画面の下書きそのままを 1 枚ずつで、まとめて生成するボタンは人が押します。編集はすべて履歴に残り、戻れます。

    利用ガイド →

  • ComfyUI のエンジン

    社内ネットワークの ComfyUI を使うことも、AWS で GPU のエンジンを動かすこともできます。登録は管理者が行います。

    利用ガイド →

  • GPU は必要なときだけ AWS 版のみ

    ecs-ec2 版では、ジョブが来たときに GPU インスタンスを起動し、手が空けば止めます。最初の 1 件は約 3 分待ちます。

    利用ガイド →

  • llama.cpp のセッション

    Qwen3・GPT-OSS・Gemma などのオープンなモデルを、サインインなしで 1 本のセッションとして動かします。冷えた状態の最初のターンは数分かかります。

    利用ガイド →

  • どのセッションからも画像を 既定はオフ

    セッションから画像生成をツールとして呼べるようにします。

    利用ガイド →

キーボード・スマホ・音声

マウスなしでも、スマホからでも、耳だけでもフリートを追えます。

  • コマンドパレット

    Ctrl/⌘ P でセッション・コマンド・変更ファイル・ファイルを探せます。自分を待っているセッションが先頭に出ます。

    利用ガイド →

  • リーダーキー

    Ctrl/⌘ K で、短いキーの連続で操作するコマンドメニューが開きます。

    利用ガイド →

  • 次の要対応へ

    Alt U で、答えを待っているセッション、次に未読の通知がある所へ移ります。

    利用ガイド →

  • ペイン

    最大 4 × 2 のペインを並べられます。どのペインもブラウザの別タブへ切り出せます。

    利用ガイド →

  • スマホで

    左右のスワイプで実行中のセッションを切り替えます。端末の下には Esc・Tab・矢印・^C などの制御キーが並びます。

    利用ガイド →

  • 読み上げ 既定はオフ

    回答をセッションごとの声で読み上げ、声の左右はペインの位置に合わせます。声はずんだもん（VOICEVOX、管理者が起動）または Amazon Polly。

    利用ガイド →

統治と管理

どのエージェントにも届くルールと、管理者が握れる統制。

  • 3 層のエージェント指示

    運用者が決めるワークスペースの方針、自分のエージェントへの指示、リポジトリの CLAUDE.md / AGENTS.md。それぞれの CLI の作法で届けます。

    利用ガイド →

  • エージェントメモリのスナップショット

    Claude Code と Codex が自分で覚えた記憶を、動いた後にスナップショットします。巻き戻せて、巻き戻しも取り消せます。

    利用ガイド →

  • 使わないモデル

    契約で追加料金がかかるモデルを隠せます。選択肢から消え、そのモデルを指定した起動は断られます。

    利用ガイド →

  • 監査ログ

    変更の操作を記録します。端末の入出力は保存しません。

    利用ガイド →

  • メンバーごとの上限

    同時に動かせるセッション数と、メンバーごとのワークスペースの大きさ（メモリ・CPU・ディスク）。

    利用ガイド →

  • 接続元の制限

    テナントに接続できる IPv4・IPv6 の範囲を絞れます。

    利用ガイド →

  • テナント独自のサインイン

    テナントは独自の OIDC プロバイダーや GitHub の組織でサインインできます。配備の管理者の承認が要ります。

    利用ガイド →

使用量と費用

請求や上限に言われる前に、フリートが何を使ったかを知る。

  • 機能・エージェント・モデル別のトークン

    24 時間・7 日・30 日で見られます。トークンを報告しない呼び出しは「未計測」として数え、無料とは扱いません。
