エージェントのまわりのことを、1 か所で

トップページでは考え方を紹介しました。このページでは、具体的に何ができるかを紹介します。前半は使い方の例を 7 つ、後半は機能の一覧です。各機能には、数字があれば数字を添え、利用ガイドの該当ページへのリンクを付けました。

  • 既定はオフ使う前に設定でオンにする必要がある
  • AWS 版のみAWS 上の配備でだけ使える
  • 実験的試作段階で、今後変わる可能性がある

使い方の例

7 つの使い方

デモ用のバックエンドにつないだ Console の録画と画面写真です。クリックすると拡大します。

3 つのエージェントにレビューを分担させる 既定はオフ

Claude のセッションが設計レビューを 3 つに分け、それぞれを別のエージェントに任せます。

  1. Claude の親が子セッションを 3 本起動します。データモデルとマイグレーションは Codex、API の互換性は Antigravity、UI への影響は Muse Code。
  2. 子はそれぞれ自分の worktree で作業し、終わったら親に 1 回報告するよう指示されています。
  3. 親が 3 本の報告をまとめます。フリート俯瞰図には 4 本のレーンが時間軸に並び、起動とメッセージが矢印で描かれます。

「セッションからのセッション起動」と「セッション間メッセージ」は、どちらも既定はオフで、設定でオンにすると使えます。子の同時本数は既定 3 本（1〜10）です。

利用ガイドの「子セッション」→

障害の調査から修正まで 実験的

2 つのアシスタントで役割を分けます。一方が監視データを調べ、もう一方が修正の作業を立ち上げます。

  1. SRE アシスタントに、PagerDuty で対応中のインシデントを聞きます。アシスタントはインシデントを読み、CloudWatch のメトリクスとログから原因を絞り込みます。
  2. SRE アシスタントは読み取り専用で、何も変更できず、セッションも起動できません。そこで修正はフリート・オペレーターに頼みます。
  3. フリート・オペレーターが新しい worktree で Codex のセッションを起動し、修正を任せます。セッションからの報告は、オペレーターとの同じ会話に届きます。

アラートがチャットに自動で届く仕組みはなく、調べるときはこちらから聞きます。PagerDuty・Grafana・CloudWatch・AWS は「設定 › 運用・監視」で接続します。

利用ガイドの「運用ツール」→

チケットから PR、そしてレビューまで

左ペインの「課題管理」に、自分宛ての仕事が集まります。

  1. クエリを保存すると、GitHub の issue とプルリクエスト、Jira の課題、Bitbucket のプルリクエストが 1 つの一覧に並びます。
  2. 課題からセッションを起動すると、ブランチ名が命名規則に沿って自動で入り（例: feature/45-empty-list）、新しい worktree で作業が始まります。
  3. プルリクエストを開くと、CI・競合・レビューが見えます。「レビューを始める」で、その PR の head ブランチを新しい worktree にチェックアウトします。

一覧の行に CI と競合の印が付くのは GitHub のプルリクエストです。Bitbucket のプルリクエストでは、詳細画面で確認します。

利用ガイドの「課題管理」→

プランの承認からコミットまで、ブラウザで

この流れに端末は要りません。

  1. プランモードで起動すると、エージェントはまずプランを出します。その場で承認するか、指摘を書き込むか、別のセッションにレビューさせます。
  2. エージェントが作業を始めます。作業コピーの変更は、会話のすぐ隣に表示されます。
  3. ステージとコミットは、コミットグラフビューで自分で行います。作業コピーごとに、実際の git リポジトリを操作します。

利用ガイドの「会話を読む・返信する」→

上限で止まったら、別のエージェントへ移す

利用上限に達したセッションは、リセットを待たなくても続けられます。

  1. チャットの上に移動の案内が出て、利用枠の残っているエージェントが先頭に並びます。セッションのメニューの「別のエージェントへ移す…」からも開けます。
  2. 移動先を選びます。ダイアログには、一緒に移るもの（コミットしていない変更、まだ push していないコミット、送っていない指示）が並びます。
  3. 新しいセッションは同じ作業コピーで起動し、まず会話の引き継ぎファイルを読みます。要約を AI が書くことはなく、元のセッションは止まります。

移動先にできるのは Claude Code、Codex、OpenCode、Copilot、Antigravity、Muse Code、Kiro です。作業中のセッションや、質問・プランの返事を待っているセッションは、先に終わらせるか答えてから移します。

セッションの移動、利用ガイド →

1 つのメモリを、どのエージェントでも 既定はオフ

あるセッションが覚えたことを、次のセッションは種類が違っても知っています。

  1. 設定でエージェントメモリをオンにします。どの種類のセッションにもメモリのツールが付き、Claude Code 自身のメモリも取り込めます。
  2. Claude Code のセッションが、決済のテストの流し方を保存します。翌朝、Codex のセッションは作業の前にそれを読みます。
  3. どのメモリにも、書いたエージェントとセッションが残ります。Console からピン留め・編集・忘れさせることも、変更の取り消しもできます。

終わったセッションからの提案は別のスイッチで、こちらも既定はオフです。自分の Claude Code や Claude Desktop からは /mcp 経由で、claude.ai からはメモリ専用の /mcp/memory 経由でメモリを使えます。

スマホで答える

席を離れていても、Console はスマホのブラウザで動きます。

  1. セッション一覧で、どのセッションが自分を待っているかが分かります。
  2. 開いて、カードの質問に答えます。席にいるときと同じ操作です。
  3. エージェントは止まったところから作業を再開し、終わると一覧に完了と表示されます。

チャットブリッジをつなぎ「返信で操縦（双方向）」をオンにすれば（既定はオフ）、そのセッションの Slack や Discord のスレッドからも答えられます。

セッション同士の協調

セッションが別のセッションを起動し、メッセージを送り合えます。フリート・オペレーターがあなたの代わりにセッションを起動し、指示します。

  • 子セッション 既定はオフ

    1 つのセッションから、子セッションを同時に 3 本まで（設定で 1〜10）起動できます。子には 9 種類のどのエージェントも使え、それぞれ新しい worktree で動きます。子がさらに子を起動することはできません。子は作業が終わったら親に 1 回報告するよう指示されます。

    利用ガイド →

  • セッション間メッセージ 既定はオフ

    依頼・質問・回答・共有の 4 種類。相手が停止中なら、再開させてから届けます。1 通 16 KiB まで、送信元ごとに 1 分間 6 通まで。

    利用ガイド →

  • フリート俯瞰図

    セッションごとのレーンを時間軸に並べ、子は親の下に置きます。起動・引き継ぎ・指示・メッセージはすべて矢印で描きます。

    利用ガイド →

  • プランを別のモデルにレビューさせる

    承認待ちのプランから「別セッションでレビュー」を選び、別のエージェントとモデルにレビューさせます。

    利用ガイド →

  • フリート・オペレーター

    セッションの起動・指示・停止・再開を代わりに行う組み込みのアシスタント。リソースを消費する起動の前には、あなたに確認します。

    利用ガイド →

  • セッション報告と自動走行

    オペレーターが指示したセッションは、作業が一段落したとき、質問やプランで止まったとき、異常終了したときに報告します。オペレーターは報告に自分で返信し、人を介さない返信は既定で 10 回、最大 50 回まで続けます。自動走行（既定はオフ）をオンにすると、定型的な質問にも答え、プランをレビューから承認まで進めます。

    利用ガイド →

  • 引き継ぎ

    会話を別のエージェントへ引き継ぎます。要約はオペレーターが下書きし、あなたが確かめてから始まります。

    利用ガイド →

  • 別のエージェントへ移す

    AI の要約を挟まずに、別の種類のエージェントで続けます。会話は引き継ぎファイルに書き出され、新しいエージェントが同じ作業コピーで起動し、元のセッションは止まります。利用上限で止まったセッションには、移動の案内が出ます。

    利用ガイド →

エージェントメモリ

どの種類のエージェントも共有する 1 つのメモリと、各 CLI が自分で覚えた記憶のスナップショットです。

  • どのエージェントにも同じメモリ 既定はオフ

    どの種類のエージェントも、MCP ツールで同じメモリを読み書きします。範囲はユーザー全体とプロジェクトごとの 2 つです。ピン留めしたメモリは、エージェントが作業の始めに読む一覧の先頭に来ます。検索は既定で 20 件、最大 50 件を返します。

    利用ガイド →

  • 変更と書き手がすべて残る

    Console は、変更ごとにそれを書いたエージェントとセッションを並べます。メモリの編集・ピン留め・忘れさせることも、忘れさせたものを戻すことも、過去の版の削除や変更の取り消しもできます。

    利用ガイド →

  • 終わった会話からメモリを提案 既定はオフ

    終わった会話を読み直して、メモリを提案します。承認するまでは何も保存されません。今のところレビューを動かせるのは Claude Code だけで、補助の呼び出しはワークスペースごとに 1 日 250 回までです。自動で動かすかどうかは別のスイッチで、こちらも既定はオフです。

    利用ガイド →

  • エージェントが覚えたことを取り込む

    Claude Code の自動メモリ、Muse Code のメモリ、メモリのバンドルを取り込めます。Claude Code 自身のメモリへの書き戻しもできます。

    利用ガイド →

  • 自分の Claude から使う 既定はオフ

    別のマシンの Claude Code や Claude Desktop からは /mcp 経由で、claude.ai からはメモリ専用の /mcp/memory 経由でメモリを読めます。許可すれば書き込みもできます。接続には MCP トークンを使うか、運用者がオンにしていれば OAuth でサインインします。テナント管理者は止めることもできます。

    利用ガイド →

  • メモリのスナップショット

    Claude Code と Codex が自分で覚えた記憶を、エージェントが止まって数分後に保存します。以前の状態に戻せるうえ、戻す直前の状態も保存されるので、戻したこと自体も取り消せます。

    利用ガイド →

メンバーと一緒に働く

同じテナントのメンバーの間で、依頼やセッションを渡し、利用上限の状況を見せ合います。

  • メンバーに頼む: 受信箱

    同じテナントのメンバーに、メッセージや依頼を送れます。セッションも 5 つまで添えられます。依頼は受け取った 1 人が引き受け、そこからセッションを始め、PR とブランチを記録して、完了にします。宛先は 20 人まで、送信は 1 時間に 30 回までです。

    利用ガイド →

  • セッションを別のメンバーに渡す

    チャットの引き継ぎカードから、共有している相手にセッションを渡せます。push していない作業が失われるときは、「push してから送る」で先に push します。

    利用ガイド →

  • 利用上限ボード 既定はオフ

    利用上限に対する自分の状況を、メンバーに見せられます。見せる範囲は、状態のみ・帯・正確な値から選びます。値は 60 分で古い扱いになり、テナント管理者はボードをオフにできます。

    利用ガイド →

ファイルを読む・直す

エージェントが書いたものもチームの資料も、Console の中のファイルビュアーで開けます。

  • コード

    約 30 言語のシンタックスハイライト、git 上で変更された行の印、10,000 行までのミニマップ。

    利用ガイド →

  • Markdown と Mermaid

    Mermaid の図をその場で描き、フロントマターは項目の一覧で表示します。path:行 形式のリンクから、そのファイルの該当行を開けます。

    利用ガイド →

  • Marp スライド

    marp: true の Markdown はスライドとして開きます。

    利用ガイド →

  • draw.io の図

    ネットワークに接続していなくても表示できます。図の編集には対応しておらず、編集できるのは XML だけです。

    利用ガイド →

  • PDF

    文字を選択でき、拡大もできます。フォントを埋め込んでいない日本語の PDF も表示できます。

    利用ガイド →

  • Office・ODF・EPUB

    Word・Excel・PowerPoint・OpenDocument・EPUB を、ブラウザの中で Markdown に変換して表示します（40 MB まで）。簡易プレビューなので、書式・図形・画像は再現しません。

    利用ガイド →

  • 画像とギャラリー

    PNG・AVIF・SVG などを表示し、8 倍まで拡大できます。ギャラリーのペインで画像を一覧でき、生成した画像はその設定もワンクリックで確認できます。

    利用ガイド →

  • 編集と AI の提案

    保存の競合を検出します。AI が提案した書き換えは、適用する前に差分で確かめられます。1 回に保存できるのは 2 MiB までです。

    利用ガイド →

  • フォルダからシェルを開く

    フォルダを右クリックすると、そのフォルダでシェルのセッションを始められます。セッションの名前はフォルダ名になります。

    利用ガイド →

  • フォルダを zip でダウンロード

    まとめられるのはファイル 20,000 個、512 MiB までで、.git と node_modules は含めません。

    利用ガイド →

  • まだ対応していないもの

    数式（KaTeX）、CSV の表表示、Jupyter ノートブック、動画・音声。これらはテキストとして開くか、開けません。

    利用ガイド →

作業の入口

チケット、プルリクエスト、自分用のメモ、スケジュール。どれからでもセッションを始められます。

  • 3 つのトラッカーを 1 つの受信箱に

    GitHub の issue とプルリクエスト、Jira の課題、Bitbucket のプルリクエストを 1 つの一覧に。約 5 分ごとに更新します。

    利用ガイド →

  • CI と競合がひと目で

    GitHub のプルリクエストは一覧の行に CI と競合の印が付きます。詳細画面では CI・競合・レビュー・差分の量を確認できます。

    利用ガイド →

  • チケットに合わせたブランチ名

    課題から起動すると、ブランチ名と分岐元が命名規則から入ります。

    利用ガイド →

  • プルリクエストからレビュー

    「レビューを始める」で、そのプルリクエストの head ブランチを新しい worktree にチェックアウトします。

    利用ガイド →

  • メモキュー

    スマホでメモを書き留め、席に戻ってから PC でセッションへ送れます。メモは端末ではなくアカウントごとに保存されます。アシスタントに整理させることもできます。

    利用ガイド →

  • 定時実行

    フリート・オペレーターに「毎晩 2 時に…」と頼むだけで設定できます。ワークスペースが停止していても、時刻になれば起動して実行します。

    利用ガイド →

Console の中の Git

作業コピーと worktree ごとに、実際の git をそのまま操作できます。並行作業に必要な後片付けの機能も揃っています。

  • コミットグラフ

    ブランチのレーンと差分、ステージとコミット、サブモジュールのグラフまで。

    利用ガイド →

  • worktree と親の差

    worktree ごとに、親と比べた状態（同じ・未マージ・早送り可・分岐）を表示し、親の変更をワンクリックで早送り（fast-forward）で取り込めます。

    利用ガイド →

  • ごみ箱から復元

    worktree を削除しても、コミット・ブランチ・未コミットの変更は記録されます。復元すると、セッションも含めて元の場所に戻ります。

    利用ガイド →

  • 内蔵の Git ホスティング

    Git LFS 付きの内部リポジトリを、テナントの中で共有できます。リポジトリ数と LFS の容量の上限は管理者が設定します。

    利用ガイド →

  • サブモジュールと LFS

    サブモジュールはクローンと一緒に取得します。SSH の URL は認証が通るよう HTTPS に書き換えます。

    利用ガイド →

  • Git Flow

    リポジトリの行から Git Flow を初期化できます。書くのは設定だけで、コミットもチェックアウトもしません。

    利用ガイド →

  • Subversion

    SVN のリポジトリもチェックアウトできます（認証情報は保存可）。worktree とコミットグラフはありません。

    利用ガイド →

エージェントのまわりの開発環境

データベース、ブラウザ、プレビューをワークスペースの中に。Docker は要りません。

  • 作業コピーごとのデータベース

    作業コピーごとに Postgres または MySQL 8.4。Docker は要りません。30 分間接続が無ければサーバーは止まります。

    利用ガイド →

  • ブラウザペイン

    開発サーバーの画面を、Console の中の実際のブラウザで確認できます。HMR・WebSocket・Cookie も動きます。ワークスペースごとに 2 つまで、PC・タブレット・スマートフォンで使えます。ECS の Fargate と GKE（プレビュー）では使えません。

    利用ガイド →

  • プレビュー URL

    ポートごとに URL が発行され、同じテナントのメンバーに見せたり、一時的にサインインなしで開けるようにしたりできます。プレビュー用サブドメインを発行する配備でだけ使えます。

    利用ガイド →

  • ブラウザを人に渡す

    エージェントがワンタイムコードの入力で止まったら、その画面をあなたに渡します。コードを入れて「操作完了」を押すだけです。ECS の Fargate と GKE（プレビュー）では使えません。

    利用ガイド →

  • 本物の端末

    素のシェルや、ターミナル（CLI）で起動したエージェントには、端末（PTY）として接続できます。スマホには制御キーの列が出ます。マネージドのセッションはチャットの表示だけです。

    利用ガイド →

  • サインイン済みの CLI

    どのセッションでも、gh・jira・bkt があなたの接続でサインインしています。エージェントは、シェルにトークンを置かずに GitHub・Jira・Bitbucket を使えます。jira のラッパーは不安定なネットワークでも読み取りをやり直し、コメントの編集と削除もできます。

    利用ガイド →

  • プレビュー URL で Google サインイン

    Google でサインインするアプリは、プレビュー URL では開発用の IdP でサインインできます。テスト用ペルソナと、そのまま貼れる設定が用意されています。プレビュー用サブドメインがある配備では、既定でオンです。

    利用ガイド →

チャットとアシスタント

自分用に作れるアシスタントと、エージェントの回答を読み、返信するための補助機能。

  • 自分のアシスタント

    役割（ペルソナ）、エージェントとモデル、ツールの権限（なし・AF 読み取り・AF 書き込み）を指定して、自分用のアシスタントを作れます。

    利用ガイド →

  • ターンを使わない翻訳

    「翻訳」は、セッションの外で 1 回だけモデルを呼び、エージェントの回答を自分の言語に翻訳します。セッションのターンは消費しません。

    利用ガイド →

  • 返信候補

    自分の過去の返信から候補を作り、チップとして表示します。AI は使いません。✨ を押したときだけ AI に聞き、トークンを使います。

    利用ガイド →

  • 圧縮しても残る作業計画

    長くなったアシスタントの会話を圧縮しても（90% を超えると自動）、作業計画は一字一句そのまま引き継ぎます。

    利用ガイド →

  • 発言から分岐

    自分の過去の発言から会話を分岐させ、元の流れを残したまま別の方向を試せます。

    利用ガイド →

  • 会話の途中でエージェントを替える

    アシスタントの会話を、続きのまま別のエージェントやモデルへ移せます。

    利用ガイド →

  • Slack と Discord 既定はオフ

    セッションごとにスレッドができます。「返信で操縦（双方向）」をオンにすれば、そこからボタンで答えられます。

    利用ガイド →

  • ターン中の追撃を溜める

    追撃をすぐに送らず、送信待ちに溜められます。エージェントの手が空くと 1 ターンずつ送られ、途中で編集や並べ替えも、1 つだけ今すぐ送ることもできます。

    利用ガイド →

  • 会話を Markdown で書き出す

    セッションのメニューから、会話だけ・ツール名つき・ツールの出力つきの 3 段階で書き出せます。秘密情報らしい文字列は伏せます。

    利用ガイド →

運用と SRE

監視をチャットから読み、AWS と Google Cloud のコマンドは自分の権限で実行します。

  • SRE アシスタント 実験的

    PagerDuty・Grafana・CloudWatch・AWS を読みます。読み取り専用で、セッションは起動できません。アラートが自動で届く仕組みはなく、調べるときはこちらから聞きます。

    利用ガイド →

  • AWS のツールは読み取りから

    Agent Toolkit for AWS は読み取り専用で始まります。書き込み用のツールは別の設定でオンにするもので、オンにすると実際のリソースを変更できます。

    利用ガイド →

  • AWS コマンドは指定したアカウントでだけ実行

    af-aws-exec は自分のプロファイルでコマンドを実行し、指定したアカウントのものでなければ断ります。ワークスペース自身のロールに黙って切り替わることはありません。

    利用ガイド →

  • SSM でログイン

    社内のホストへ SSM Session Manager で入ります。サインインは IAM Identity Center で、AWS の秘密情報を Agent Fleet に保存しません。

    利用ガイド →

  • Google Cloud を自分として使う

    af-gcloud-exec は、gcloud、GKE への kubectl、Terraform を、あなたの Google Cloud のプロファイルで動かします。トークンは短命で、裏で更新されます。Google の資格情報は保存しません。

    利用ガイド →

MCP

エージェントに自分のツールを渡し、外から Agent Fleet を操作します。

  • 自分の MCP サーバー

    リモートのサーバーを、認証なし・Bearer トークン・カスタムヘッダー・OAuth のどれかで登録できます。stdio のサーバーも動かせます。秘密情報は暗号化して保存し、OAuth のトークンはワークスペース内の中継の奥に置くので、CLI の設定には書かれません。セッションと、自分で作ったアシスタントに付けられます。

    利用ガイド →

  • 外部のエージェントから操作

    Claude Code や Claude Desktop から、MCP トークンで自分のワークスペースを操作できます。範囲は読み取り・書き込み・管理の 3 段階で、期限は既定 90 日、取り消しもできます。運用者がオンにすれば、claude.ai・ChatGPT・Claude Code・Codex はトークンの代わりに OAuth でサインインして、読み取りか書き込みの権限で接続できます。この接続は、30 日使わないか、許可してから 90 日たつと切れます。

    利用ガイド →

  • テナントに配る

    テナント管理者が、リモートの MCP サーバーをテナント全員に一度に配れます。認証情報は、共通の値を配る、各メンバーが入力する、各メンバーが自分で OAuth サインインする、の 3 通りから選べます。

    利用ガイド →

  • 外部通信の統制

    配備の運用者は、ワークスペースの接続先を記録し、そこから許可リストを作れます。メンバーは設定から接続先の許可を申請します。許可リストでワークスペースを実際に制限できるのは、AWS でオプションの egress ゲートウェイ（プレビュー）を通したときだけです。

    利用ガイド →

画像生成と自前のエンジン

管理者が用意したエンジンか、自分の Codex や Antigravity のサインインで画像を生成できます。オープンなモデルも配備の中で動かせます。

  • スタジオ

    エージェントと話しながら下書きを直します。エージェントが自分で試せるのは、画面の下書きどおりに 1 枚ずつだけで、まとめて生成するボタンは人が押します。編集はすべて履歴に残り、前の状態に戻せます。

    利用ガイド →

  • ComfyUI のエンジン

    社内ネットワークの ComfyUI を使うことも、AWS で GPU のエンジンを動かすこともできます。登録は管理者が行います。

    利用ガイド →

  • GPU は必要なときだけ AWS 版のみ

    ecs-ec2 版では、ジョブが来たときに GPU インスタンスを起動し、使われなくなれば停止します。最初の画像のジョブは起動を約 3 分、チャットのエンジンは約 9 分待ちます。

    利用ガイド →

  • llama.cpp のセッション

    Qwen3・GPT-OSS・Gemma などのオープンなモデルを、サインインなしで 1 本のセッションとして動かします。起動直後の最初のターンには数分かかります。

    利用ガイド →

  • セッションから画像を生成 既定はオフ

    セッションのエージェントが、画像生成をツールとして呼び出せるようになります。

    利用ガイド →

統治と管理

どのエージェントにも届くルールと、管理者が設定できる制限。

  • 3 層のエージェント指示

    運用者が決めるワークスペースの方針と、自分のエージェントへの指示は、それぞれの CLI に合った形式で渡します。Cursor はどちらも受け取りません。3 層目はリポジトリの CLAUDE.md / AGENTS.md で、CLI が自分で読みます（opencode が読むのは AGENTS.md だけです）。

    利用ガイド →

  • 使わないモデル

    契約で追加料金がかかるモデルを隠せます。選択肢から消え、そのモデルを指定した起動は断られます。

    利用ガイド →

  • 監査ログ

    変更の操作を記録します。端末の入出力は保存しません。

    利用ガイド →

  • メンバーごとの上限

    同時に動かせるセッション数と、ワークスペースの大きさ（メモリ・CPU・ディスク）を、メンバーごとに管理者が設定できます。

    利用ガイド →

  • 接続元の制限

    テナントに接続できる IPv4・IPv6 の範囲を絞れます。

    利用ガイド →

  • テナント独自のサインイン

    テナントは独自の OIDC プロバイダーや GitHub の組織でサインインできます。配備の管理者の承認が要ります。

    利用ガイド →

  • 困りごとが見える名簿

    テナント管理者には、メンバーがカードで並びます。状態、home ディスク、セッション、最後の活動が見え、home の空きが少ないといった要対応のメンバーだけに絞り込めます。

    利用ガイド →

使用量と費用

請求が来る前、上限に達する前に、フリートがどれだけ使ったかを把握できます。

  • 機能・エージェント・モデル別のトークン

    24 時間・7 日・30 日の範囲で確認できます。トークンを報告しない呼び出しは「未計測」として数え、無料とは扱いません。

    利用ガイド →

  • API 換算相当額

    トークンを公開されている API の定価で換算した推定です。定額の契約で請求される額ではありません。

    利用ガイド →

  • 上部バーの上限チップ

    Claude・Codex・Copilot・Antigravity・Muse Code について、契約の利用上限のうちどれだけ使ったかを表示します。

    利用ガイド →

  • 上限の後に自動で再開

    利用上限で止まったターンは、上限がリセットされると自動で再開します。Claude、Muse Code、マネージドの Codex が対象です。ほかのセッションは、利用枠の残っているエージェントへ移せます。

    利用ガイド →

  • ワークスペースごとのクラウド費用 AWS 版のみ

    ワークスペースに直接ひもづく費用を、約 1 日遅れで表示します。

    利用ガイド →

  • 稼働時間のヒートマップ

    時刻と日付のマス目を、稼働時間またはセッション数で色分けします。

    利用ガイド →

  • セッションごとの予算

    セッションに米ドルで予算を付けられます。予算に届いたターンが終わるとセッションは止まり、1 ターンで予算の 2 倍 に達したら途中で止めます。金額は定価での見積もりで、報告が足りずに止められないエージェントもあります。

    利用ガイド →
