In practice

Five walkthroughs

Recorded in the Console against a demo backend. Click a recording to see it full size.

Split a review across three agents Off by default

A Claude session splits a design review three ways and gives each part to a different agent.

  1. The Claude parent starts three child sessions: Codex on the data model and migrations, Antigravity on API compatibility, Muse Code on the UI.
  2. Each child works in its own worktree and is asked to report back once when it finishes.
  3. The parent pulls the three reports together. The fleet graph shows four lanes on a time axis, with an arrow for every start and message.

Starting sessions from sessions and messages between sessions are both off until you switch them on. A parent runs 3 children at once by default (1–10).

Child sessions in the guide →

From an incident to a fix Experimental

Two assistants, two jobs: one reads the monitoring, the other starts the work.

  1. Ask the SRE assistant what is open on PagerDuty. It reads the incident, then the CloudWatch metrics and logs, and narrows down the cause.
  2. The SRE assistant is read-only: it cannot change anything or start a session. So you take the fix to the Fleet Operator.
  3. The Fleet Operator starts a Codex session in a new worktree with the fix as its task, and the session's report comes back to that conversation.

Alerts do not arrive in the chat on their own — you ask. PagerDuty, Grafana, CloudWatch and AWS are connected under Settings › Ops & monitoring.

Ops tooling in the guide →

From a ticket to a pull request, and its review

The issue tracker in the left pane gathers the work waiting for you.

  1. Save a query, and GitHub issues and pull requests, Jira issues and Bitbucket pull requests land in one list.
  2. Start a session from an issue. The branch name comes from your naming rules — feature/45-empty-list, say — in a new worktree.
  3. Open a pull request: its details show CI, merge conflicts and reviews, and “Start review” checks out the PR's own head branch in a new worktree.

CI and conflict marks sit on the list rows for GitHub pull requests; for Bitbucket they are in the details.

The issue tracker in the guide →

Approve the plan, then commit — in the browser

Nothing in this loop needs a terminal.

  1. Started in plan mode, the agent proposes a plan first. Approve it in place — or write comments on it, or have another session review it.
  2. It gets to work. The working copy's changes sit right beside the chat.
  3. Stage and commit yourself from the commit graph view: real git, per working copy.

Answering a running agent in the guide →

Answer from your phone

Away from the desk, the Console runs in your phone's browser.

  1. The sessions overview shows which session is waiting on you.
  2. Open it and answer the question on its card, as you would at a desk.
  3. It carries on where it stopped, and the list shows it done.

Or answer in the session's Slack or Discord thread, once the chat bridge is connected and “Reply to steer” is on (it is off by default).

Sessions working together

A session can start other sessions and message them; the Fleet Operator starts and steers sessions for you.

  • Child sessions Off by default

    A session starts up to 3 children at once by default (1–10), of any of the 9 agent kinds, each in a new worktree. One level deep: children cannot start their own. Each is asked to report back once.

    In the guide →

  • Messages between sessions Off by default

    Four kinds — request, question, answer and FYI. A stopped recipient is resumed to receive it. Up to 16 KiB a message and 6 a minute per sender.

    In the guide →

  • Fleet graph

    One lane per session on a time axis, children under their parent, and an arrow for every start, handoff, instruction and message.

    In the guide →

  • A second opinion on the plan

    From a plan waiting for approval, “Review in another session” lets you pick a different agent and model to review it.

    In the guide →

  • Fleet Operator

    A built-in assistant that starts, instructs, stops and resumes sessions for you — and asks before starting anything that uses resources.

    In the guide →

  • Session reports and Autopilot Off by default

    Sessions report to the operator when they go idle, ask something or exit abnormally. With Autopilot on it answers routine questions itself — 10 unattended replies by default, 50 at most.

    In the guide →

  • Handoff

    Carry a conversation over to another agent. The operator drafts the summary, and you confirm it before anything starts.

    In the guide →

Reading and editing files

The file viewer opens what agents write and what your team keeps — without leaving the Console.

  • Code

    Highlighting for about 30 languages, change bars on lines git sees as modified, and a minimap up to 10,000 lines.

    In the guide →

  • Markdown and Mermaid

    Mermaid diagrams render in place, front matter shows as a property list, and path:line links open the file at that line.

    In the guide →

  • Marp slides

    A Markdown file with marp: true opens as a slide deck.

    In the guide →

  • draw.io diagrams

    Rendered with no network access. Viewing only: you can edit the XML, not the drawing.

    In the guide →

  • PDF

    Text selection and zoom. Japanese PDFs without embedded fonts render too.

    In the guide →

  • Office, ODF and EPUB

    Word, Excel, PowerPoint, OpenDocument and EPUB, converted to Markdown in your browser, up to 40 MB. A plain preview: layout, shapes and images are not reproduced.

    In the guide →

  • Images and the gallery

    PNG to AVIF and SVG, zoomable to 8×. A gallery pane collects pictures; a generated one's settings are one click away.

    In the guide →

  • Editing, with AI proposals

    Save conflicts are detected, and an AI's proposed change is shown as a diff before you apply it (2 MiB per change).

    In the guide →

  • Not supported (yet)

    Math (KaTeX), CSV as a table, Jupyter notebooks, and video or audio. These open as text, or not at all.

    In the guide →

Git, in the Console

Real git per working copy and worktree, with the housekeeping that parallel work needs.

  • Commit graph

    Branch lanes and diffs, staging and commit, and the graphs of submodules.

    In the guide →

  • Worktrees against their parent

    Each worktree shows where it stands against its parent — even, unmerged, fast-forwardable or diverged — with a one-click fast-forward.

    In the guide →

  • Restore from the trash

    Deleting a worktree keeps its commit, branch and uncommitted changes. Restoring puts it back at the same path, sessions included.

    In the guide →

  • Built-in git hosting

    Internal repositories with Git LFS, shared within your tenant. An administrator sets how many and how much LFS storage.

    In the guide →

  • Submodules and LFS

    Submodules are fetched with the clone, and SSH URLs are rewritten to HTTPS so they authenticate.

    In the guide →

  • Git Flow

    Initialize Git Flow for a repository from its row. It writes the configuration only — no commit, no checkout.

    In the guide →

  • Subversion

    Check out SVN repositories too, with saved credentials. No worktrees or commit graph there.

    In the guide →

A development environment around the agent

Databases, a browser and previews inside the workspace, with no Docker required.

  • Databases per working copy

    Postgres or MySQL 8.4 for each working copy, with no Docker. The server stops after 30 idle minutes.

    In the guide →

  • Browser pane

    Your dev server in a real browser inside the Console — HMR, WebSockets and cookies work. 2 per workspace, on desktop and tablet.

    In the guide →

  • Preview URLs AWS only

    A URL per port that you can show to your tenant, or open without sign-in for a while. Issued only where the deployment provides preview subdomains.

    In the guide →

  • Hand the browser to a person

    When an agent reaches a one-time code, it hands you the page. You type the code and press “Action complete”.

    In the guide →

  • A real terminal

    Every session, agent or plain shell, is attachable as a live PTY — with a control-key row on phones.

    In the guide →

Operations and SRE

Read your monitoring from a chat, and run AWS commands as yourself.

  • SRE assistant Experimental

    Reads PagerDuty, Grafana, CloudWatch and AWS. Read-only: it cannot start sessions, and alerts do not arrive on their own — you ask.

    In the guide →

  • AWS tools, read-only first

    The Agent Toolkit for AWS starts read-only. Write tools are a separate switch, and they can change real resources.

    In the guide →

  • AWS commands run only in the account you name

    af-aws-exec runs a command as your profile and refuses unless it belongs to the account you name — so nothing falls back to the workspace's own role.

    In the guide →

  • SSM login

    Reach in-house hosts through SSM Session Manager, signing in with IAM Identity Center. No AWS secrets are stored in Agent Fleet.

    In the guide →

MCP

Bring your own tools to the agents, and drive Agent Fleet from outside.

  • Your MCP servers

    Register stdio or remote HTTP servers, with secrets stored encrypted. Attach them to sessions and to the assistants you create.

    In the guide →

  • Drive it from an external Claude

    Operate your workspace from Claude Code or Claude Desktop with an MCP token: read, write or admin scope, expiring after 90 days by default, revocable.

    In the guide →

  • Distribute to the tenant

    A tenant administrator hands a remote MCP server to everyone in the tenant at once.

    In the guide →

  • Outbound control

    The deployment's operator can log or enforce outbound MCP traffic against an allowlist; members request access from Settings.

    In the guide →

    In the guide →

  • ComfyUI engines

    Point the deployment at your own ComfyUI on the network, or run GPU engines on AWS. An administrator registers them.

    In the guide →

  • A GPU only when it is needed AWS only

Keyboard, phone and voice

Move through the fleet without the mouse, from a phone, or by ear.

  • Command palette

    Ctrl/⌘ P finds sessions, commands, changed files and files — sessions waiting on you first.

    In the guide →

  • Leader key

    Ctrl/⌘ K opens a command menu of short key sequences.

    In the guide →

  • Next thing that needs you

    Alt U jumps to the next session waiting on your answer, then to unread notifications.

    In the guide →

  • Panes

    Up to 4 × 2 panes side by side; any pane pops out into its own browser tab.

    In the guide →

Governance and administration

Rules that reach every agent, and controls an administrator can hold.

  • Three layers of instructions

    The fleet policy from the operator, your own agent instructions, and each repository's CLAUDE.md / AGENTS.md — delivered in each CLI's own idiom.

    In the guide →

  • Agent memory snapshots

    What Claude Code and Codex remember on their own is snapshotted after each run. Roll it back — and undo the rollback.

    In the guide →

  • Models you don't use

    Hide the models your plan bills extra for: they leave the pickers, and launches naming them are refused.

    In the guide →

  • Audit log

    Changes are recorded; terminal input and output are not stored.

    In the guide →

  • Per-member limits

    Concurrent sessions, and each member's workspace size: memory, CPU and disk.

    In the guide →

  • Allowed networks

    Limit a tenant to IPv4 and IPv6 ranges you list.

    In the guide →

  • A tenant's own sign-in

    A tenant can bring its own OIDC provider or GitHub organization, once the deployment's administrator approves it.

    In the guide →

Usage and cost

Know what the fleet uses before the bill, or the limit, tells you.

  • Tokens by feature, agent and model

    Over 24 hours, 7 or 30 days. Calls that report no tokens count as unmeasured, never as free.

    In the guide →

  • API-equivalent cost

    Tokens priced at the published API list price — an estimate, not what a flat subscription bills you.

    In the guide →

  • Plan limits on the top bar

    How much of each plan's limit is used, for Claude, Codex, Copilot, Antigravity and Muse Code.

    In the guide →

  • Resume after a limit

    A turn cut short by a usage limit picks up again once the limit resets — for Claude, and for Codex when Managed.

    In the guide →

  • Cloud cost per workspace AWS only

    The cost directly attributable to each workspace, about a day behind.

    In the guide →

  • Running-time heatmap

    Hours of the day against dates, coloured by time running or by session count.

    In the guide →
